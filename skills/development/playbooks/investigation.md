### Investigation

**You own a cited answer. Read-only; a fix is a separate request.**

1. Size the question. Narrow: read and answer in one pass. Broad: split into parts, explore in parallel read-only workers, combine the reduced findings.
2. Run `investigate` in the matching mode: Explain for how it works, Diagnose for what is wrong, Trace for why it is this way. Look at the real thing: run it, open it, query it. Code shape and summaries are leads, not proof.
3. Cite every claim to a file and line, commit, task, message, metric, or screenshot. Label inference as inference. Keep competing explanations alive until evidence rules them out, and show contradictions rather than picking the convenient source.
4. For "are we sure?" or "is this right?", add a critique sorted into fix now, worth considering, noted, and dismissed with the reason.
5. Name the gaps: what you searched and did not find.
6. If a fix is clearly in scope and the user asked for one, route to the matching playbook; otherwise propose it with scope and tradeoffs and stop.

**Reply:** the answer first, then only the flow, citations, and caveats needed to trust it.
